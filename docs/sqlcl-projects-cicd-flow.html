SQLcl Projects CI/CD Flow

Database changes are captured in development branches, validated before merge, accumulated in dist/releases/next on main, and closed into versioned release artifacts only when the team decides to publish.

Developer branch Database-first changes are exported and staged.
Pull request validation project verify checks the staged branch output.
Main accumulation Merged changes stay pending in dist/releases/next.
Manual release project release and gen-artifact create the ZIP.

End-to-End Process

Local database work
SQLcl Project command
Pending changelog state
Validation gate
GitHub operation

Repository State Transition

Before the manual release

The main branch can contain multiple merged development cycles.

  • dist/releases/next contains the accumulated pending changelogs.
  • src/database reflects the latest exported schema source.
  • No immutable release artifact has been created yet.

After the manual release

The workflow closes the pending SQLcl Project release.

  • Pending changelog content from dist/releases/next is moved into dist/releases/<version>.
  • dist/releases/next/.gitkeep is recreated so the empty next folder stays visible in Git.
  • dist/releases/main.changelog.xml points at the closed version.
  • artifact/MyAppCICD-<version>.zip is generated and attached to GitHub Releases.
  • The closed release state is committed back to main.
Release behavior: the release workflow does not need a database connection. It only closes already staged repository changes and packages the SQLcl Project artifact.

Operational Sequence

1

Develop

Apply changes in the development database and run dev_cycle.sh to export and stage them.

2

Validate

Push the branch. GitHub Actions runs project verify before the pull request is merged.

3

Accumulate

Merge approved branches into main. Pending release content stays in next.

4

Release

Run the manual SQLcl Project Release workflow from main and provide the version.

5

Restart

The closed release is committed to main, and next remains visible with no pending changes.

6

Deploy

Run the manual deploy workflow to list artifacts, preview SQL, and deploy the selected release to production.
